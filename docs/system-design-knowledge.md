## 系统设计答题框架

### 标准答题流程（4S 法）
1. **Scene（场景）**：需求澄清（功能/非功能/规模）
2. **Shape（架构）**：高层架构图 + 核心模块
3. **Scale（扩展）**：数据库 Schema + API 设计 + 扩展性
4. **Trade-off（权衡）**：关键决策的 Why & Why Not

### 面试加分项
- 主动澄清需求（不要假设）
- 量化估算（QPS、存储、成本）
- 画出架构图（ASCII 即可）
- 讨论 Trade-off（每个选择说为什么）
- 提出扩展方向（未来演进）

## 1. 设计 ChatGPT 类对话系统

### 需求澄清
- **功能**：文本对话、多轮记忆、流式输出、多模态、文件上传
- **非功能**：首字 < 1s，生成 > 30 tokens/s，99.9% 可用，100K 并发
- **规模**：1 亿 DAU，每用户日均 10 轮，每轮 500 in + 300 out tokens

### 架构
```
┌─────────┐     ┌──────────┐     ┌──────────┐     ┌─────────┐
│  Client  │────▶│  Gateway │────▶│  Session │────▶│   LLM   │
│(Web/App) │◀────│(LB+Auth) │────▶│  Manager │────▶│ Service │
└─────────┘     └──────────┘     └──────────┘     │ (vLLM)  │
                                                   └─────────┘
```

### 核心模块
1. **流式输出**：SSE/WebSocket + 背压控制 + 断线重连
2. **上下文管理**：滑动窗口 + 摘要压缩 + Token 计数
3. **会话存储**：Redis（热）+ PostgreSQL（冷）
4. **推理服务**：vLLM + PagedAttention + 连续批处理
5. **安全合规**：输入审核 + 输出审核 + Prompt Injection 防御

### Trade-off
| 决策 | 选择 | 原因 |
|------|------|------|
| 流式协议 | SSE | 简单、自动重连 |
| 会话存储 | Redis | 低延迟 |
| 上下文策略 | 混合 | 短对话窗口 + 长对话摘要 |
| 模型部署 | 混合 | 核心自研 + 兜底 API |

## 2. 设计智能客服

### 架构
```
用户输入 → 意图识别 → 路由分发
                ├── FAQ 检索（向量数据库）
                ├── 多轮对话（状态机/槽位填充）
                └── Agent 工具调用（订单查询/退款）
                        └── 知识库（RAG Pipeline）
                              └── 兜底：转人工
```

### 核心模块
1. **意图识别**：分类模型（BERT/LLM）→ 路由到不同处理流
2. **FAQ 检索**：语义检索（Embedding + 向量数据库）
3. **多轮对话**：状态机管理 + 槽位填充
4. **Agent 工具**：Function Calling 调用内部 API
5. **兜底策略**：置信度低 → 转人工

### 评估指标
- 解决率（Resolution Rate）
- 用户满意度（CSAT）
- 转人工率
- 平均处理时间

## 3. 设计代码助手（Copilot）

### 核心挑战
- 延迟 < 200ms
- 上下文：当前文件 + 相关文件 + 项目结构
- 接受率 > 30%
- 代码隐私不出域

### 架构
```
IDE Plugin → Context Builder → Retrieval Engine → Inference → Post Process
                                (Speculative Decoding)
```

### 核心模块
1. **上下文构建**：当前文件 + 相关文件检索 + AST + Import 分析
2. **推理优化**：Speculative Decoding + KV Cache 复用 + INT4 量化
3. **隐私保护**：本地 Embedding + 代码脱敏 + 私有部署
4. **评估**：接受率 + 编辑相似度 + 延迟分布

### Trade-off
| 决策 | 选择 | 原因 |
|------|------|------|
| 推理加速 | Speculative Decoding | 延迟降低 2-3x |
| 上下文 | 混合检索 | 精确 + 语义互补 |
| 部署 | 混合 | 公有云弹性 + 私有云安全 |

## 4. 设计文档问答系统

### 架构
```
文档上传 → 解析（PDF/HTML/表格/图片）→ 结构化存储
                                              ↓
用户问题 → Query 理解 → 检索（多模态）→ 生成 → 答案 + 引用溯源
```

### 核心模块
1. **多模态解析**：PDF（Nougat）+ 表格（TATR）+ 图片（GPT-4V）
2. **结构化存储**：文本块 + 表格结构 + 图片描述 + 元数据
3. **多模态检索**：文本检索 + 表格检索 + 图片检索
4. **引用溯源**：标注答案来源（页码、段落、表格位置）

### 评估
- 答案准确率
- 引用准确率
- 表格问答准确率
- 用户满意度

## 5. 设计 AI 搜索

### 架构
```
Query → Query 改写 → 多源检索（Web/API/知识库）→ 重排序 → LLM 摘要 → 结果 + 引用
```

### 核心模块
1. **Query 改写**：拼写纠错 + 意图识别 + 查询扩展
2. **多源检索**：Web Search API + 自有知识库 + 实时数据 API
3. **重排序**：相关性 + 时效性 + 权威性
4. **LLM 摘要**：多文档综合 + 引用标注
5. **缓存**：热门 Query 缓存 + 增量更新

### Trade-off
| 决策 | 选择 | 原因 |
|------|------|------|
| 检索源 | 多源 | 覆盖全面 |
| 摘要长度 | 动态 | 根据 Query 复杂度 |
| 实时性 | 增量更新 | 平衡新鲜度和成本 |

## 6. 设计翻译系统

### 架构
```
源文本 → 领域检测 → NMT 翻译 → LLM 后编辑 → 质量评估 → 输出
```

### 核心模块
1. **领域检测**：通用/法律/医学/技术 → 选择不同模型
2. **NMT 翻译**：M2M-100 / NLLB-200（多语言）
3. **LLM 后编辑**：流畅性 + 术语一致性 + 风格调整
4. **质量评估**：BLEU + COMET + 人工抽检

## 7. 设计推荐系统

### 架构
```
用户行为 → 特征工程 → 召回（多路）→ 精排（LLM）→ 重排 → 推荐结果
```

### 核心模块
1. **多路召回**：协同过滤 + 内容 + 热门 + 新品
2. **LLM 精排**：用户画像 + 物品特征 → 排序
3. **重排**：多样性 + 新鲜度 + 业务规则
4. **实时更新**：Flink 实时特征 + 在线学习

## 8. 通用 Trade-off 速查

| 维度 | 选项 A | 选项 B | 选择依据 |
|------|--------|--------|----------|
| 延迟 vs 质量 | 快速小模型 | 慢速大模型 | 场景决定 |
| 成本 vs 效果 | API 调用 | 自研部署 | 规模决定 |
| 精确 vs 召回 | 高精确 | 高召回 | 场景决定 |
| 实时 vs 离线 | 实时计算 | 离线批处理 | 时效性决定 |
| 集中 vs 分布 | 中心化 | 分布式 | 规模决定 |
| 通用 vs 领域 | 通用模型 | 领域微调 | 精度要求决定 |
